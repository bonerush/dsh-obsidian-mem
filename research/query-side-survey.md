# Query-side mechanisms: manufacturing a retrieval query from a short, deictic, or lexically barren prompt

Scope note: everything below was read from primary sources fetched during this session (local copies under `/tmp/qr/`). Numbers marked **[vendor]** come from the system's own authors/vendor. Anything I could not open is marked **UNVERIFIED**.

## 0. There are only five query shapes in production

(1) **No query at all** — memory stays in context; MemGPT/Letta keep "working context" as a fixed read/write block always in the prompt, with retrieval as an explicit function call ([MemGPT §2](https://ar5iv.labs.arxiv.org/html/2310.08560)). (2) **The raw prompt, verbatim** — mem0, Graphiti, essentially every `search_memory` MCP tool. (3) **A rewrite** — LangChain/LlamaIndex condense chains and the CAsT systems. (4) **The prompt plus synthetic text** — HyDE, query2doc. (5) **The prompt plus environment state** — Continue's autocomplete context, FLARE's generated span.

The single most important finding for our problem is architectural: **the largest measured gains in long-term memory come from the document side, not the query side.** LongMemEval's own system row is "round / K = V + fact / question + time" — an LLM-extracted fact list concatenated onto the *stored* value, with the query left as the question ([LongMemEval Table 2, §5.3](https://arxiv.org/html/2410.10813v2)). That raised recall@k by 9.4% and accuracy by 5.4%, and fusing the pathways *at retrieval time* underperformed fusing them *at indexing time* (fn. 4). Anthropic's "Contextual Retrieval" has the same shape: a Claude-3-Haiku prompt emits 50–100 tokens of chunk-situating context prepended **before embedding and before creating the BM25 index**, cutting top-20 failure 5.7%→3.7% (contextual embeddings), →2.9% with contextual BM25, 67% with reranking; $1.02/M document tokens with prompt caching **[vendor]** ([Anthropic](https://www.anthropic.com/engineering/contextual-retrieval)). Contextual **BM25** transfers to FTS5 verbatim.

## 1. HyDE: generate the answer, then embed it

Mechanism ([Gao et al., ACL 2023](https://ar5iv.labs.arxiv.org/html/2212.10496)): prompt an instruction-following LM with "Please write a passage to answer the question / Question: [QUESTION] / Passage:" (per-dataset variants in A.1), sample hypothetical documents, average their encoder vectors, and do kNN in *document* embedding space. The grounding step is explicitly the encoder's "lossy compressor" bottleneck that filters out hallucinated detail; they also consider the raw query itself as one hypothesis (Eq. 8). Two things matter for us: the paper assumes "the distribution of d is uni-modal, i.e. **the query is not ambiguous**. The study of ambiguous queries and diversity is left to future work" — deictic follow-ups are exactly the excluded case; and with FTS5 there is no bottleneck, so a hallucinated pseudo-document would inject its invented terms into the index lookup verbatim. There is no published measurement of HyDE on short/deictic conversational turns. Anthropic evaluated hypothetical-document embedding and "saw low performance" **[vendor]**.

## 2. query2doc: the lexical sibling, and its real cost

Same paper family, different consumer ([Wang, Yang, Wei, EMNLP 2023](https://ar5iv.labs.arxiv.org/html/2303.07678)): 4 randomly-sampled in-context examples from MS MARCO, generate a pseudo-document, then **concatenate** it with the original query. The ablation is decisive for a lexical store: TREC DL19/DL20 BM25 gives 66.2/62.9 with query+pseudo-doc, versus 51.2/47.7 query-only and 48.7/44.5 pseudo-doc-only (HyDE-style). Latency (Table 6, MS MARCO dev, top-100, single thread): BM25 alone 16 ms; "+query2doc" >2000 ms for the LLM plus 177 ms of index search — **disqualifying for a per-turn hook**. One operational detail worth stealing: GPT-4 "has a tendency to ask for clarification instead of directly generating the pseudo-documents", fixed by a system message ("You are asked to write a passage that answers the given query. Do not ask the user for further clarification."). Temperature/max-token values rendered as stripped math in my copy — **UNVERIFIED**.

## 3. LongMemEval's time-aware expansion: the cleanest negative result

The query-side half of LongMemEval is small: an LLM extracts a time range from the question, and retrieval is restricted to values whose indexed dates fall in that range ([§5.4, Table 4](https://arxiv.org/html/2410.10813v2)). With rounds as the value and K=V+fact, recall@5 goes 0.489 → 0.526 with GPT-4o extracting the range, but → **0.481 with Llama-3.1-8B**, i.e. below the no-expansion baseline; with sessions and K=V, recall@5 drops 0.639 → 0.624 on the 8B path; even GPT-4o loses NDCG@10 in one cell (0.782 → 0.758). Their diagnosis (§E.4): when the question has no temporal reference, the 8B model "mistakenly extracts a time range, which erroneously prunes out the search space, leading to a low memory recall", whereas GPT-4o refuses to produce one. **The failure mode of a bad rewrite is over-pruning, not a no-op.** Limits: the expansion is a hard filter, applied on top of a dense retriever (Stella V5 1.5B), and the method is only defined for questions that *have* a time reference; the paper reports no expansion quality metric of its own, only end recall. Also relevant: retrieved-item token budget must match the reader — Llama-3.1-8B's accuracy "drops sharply beyond 3k retrieved tokens" while GPT-4o keeps improving past 20k (§5.2).

## 4. mem0: raw query, deterministic enrichment, query-length-adaptive scoring

Current OSS `Memory.search(query, *, top_k=20, threshold=0.1, rerank=False)` ([mem0/memory/main.py](https://github.com/mem0ai/mem0/blob/main/mem0/memory/main.py)) does **not** rewrite the query; it *enriches deterministically*: `lemmatize_for_bm25(query)` (spaCy lemmas plus original -ing forms) and `extract_entities(query)` (spaCy proper nouns, quoted strings, noun compounds) — local NLP, no LLM. It over-fetches `internal_limit = max(limit * 4, 60)` from the vector store, runs `keyword_search` on the lemmatized query, and folds signals additively: `combined = (semantic + bm25 + entity_boost) / max_possible`, `ENTITY_BOOST_WEIGHT = 0.5` ([mem0/utils/scoring.py](https://github.com/mem0ai/mem0/blob/main/mem0/utils/scoring.py)). BM25 raw scores are sigmoid-normalized with **query-length-adaptive parameters**: ≤3 terms → (midpoint 5.0, steepness 0.7); ≤6 → (7.0, 0.6); ≤9 → (9.0, 0.5); ≤15 → (10.0, 0.5); else (12.0, 0.5). That tier is the only short-query-specific accommodation I found in a shipping memory system. Two caveats: candidates come *only* from semantic search (keyword hits merely re-score them), and `threshold` gates the **semantic** score before combination — in mem0 the vector path, not the lexical path, owns recall. An empty query raises `ValueError` instead of falling back; v0.1.100's `search` (default `limit=100`) likewise calls no LLM. Graph memory's read path is entity-centric — "first identifies key entities within a query, then leverages semantic similarity to locate corresponding nodes" ([mem0 paper](https://arxiv.org/html/2504.19413v1)) — and its headline +26% over OpenAI on LoCoMo, 91% lower p95 latency and >90% token savings are **[vendor]**.

## 5. Zep / Graphiti: raw query, hybrid channels, and graph seeds instead of rewrites

`graphiti.search(query, center_node_uuid=None, num_results=10)` passes the raw string to (a) Lucene BM25 via `fulltext_query()` = `lucene_sanitize(query)` plus a group filter, (b) cosine similarity on an embedded copy, (c) optionally BFS; then RRF/MMR/node-distance/episode-mentions/cross-encoder reranking ([search_config.py](https://github.com/getzep/graphiti/blob/main/graphiti_core/search/search_config.py), [recipes](https://github.com/getzep/graphiti/blob/main/graphiti_core/search/search_config_recipes.py), [search_utils.py](https://github.com/getzep/graphiti/blob/main/graphiti_core/search/search_utils.py)). Defaults: `DEFAULT_SEARCH_LIMIT=10`, `DEFAULT_MIN_SCORE=0.6`, `DEFAULT_MMR_LAMBDA=0.5`, `MAX_SEARCH_DEPTH=3`, RRF `rank_const=1`, `reranker_min_score=0`. Degenerate-query handling is explicit: past `MAX_QUERY_LENGTH=128` words `fulltext_query` returns `''`, so BM25 contributes nothing and RRF ranks on the remaining channels. The deictic fix they actually ship is **not** a rewrite: the paper notes BFS "can accept nodes as parameters for the search… particularly valuable when using **recent episodes as seeds**", so the previous turn's entities anchor retrieval ([Zep §3.1](https://arxiv.org/html/2501.13956v1)). Their reported LongMemEval +18.5% accuracy with 90% lower latency is **[vendor]**. The cross-encoder reranker is an LLM: `OpenAIRerankerClient`, `DEFAULT_MODEL='gpt-4.1-nano'`, a boolean classifier prompt scored by log-probabilities ([openai_reranker_client.py](https://github.com/getzep/graphiti/blob/main/graphiti_core/cross_encoder/openai_reranker_client.py)).

## 6. Conversational query rewriting: exact prompts, and the measurement venue

LangChain's `create_history_aware_retriever(llm, retriever, prompt)` encodes the control flow we want: if `chat_history` is empty, "we just pass input to retriever" — **no LLM call at all**; otherwise `prompt | llm | StrOutputParser() | retriever` ([history_aware_retriever.py](https://github.com/langchain-ai/langchain/blob/master/libs/langchain/langchain_classic/chains/history_aware_retriever.py)). Its default condense prompt is "Given the following conversation and a follow up question, rephrase the follow up question to be a standalone question, **in its original language**. Chat History: {chat_history} Follow Up Input: {question} Standalone question:" ([conversational_retrieval/prompts.py](https://github.com/langchain-ai/langchain/blob/master/libs/langchain/langchain_classic/chains/conversational_retrieval/prompts.py)). LlamaIndex's `CondenseQuestionChatEngine` ships the same idea: "rewrite the message to be a standalone question that captures all relevant context from the conversation" ([condense_question.py](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/chat_engine/condense_question.py)); `HyDEQueryTransform` is the synthetic-document variant ([notebook](https://github.com/run-llama/llama_index/blob/main/docs/examples/query_transformations/HyDEQueryTransformDemo.ipynb)).

Measurement exists, and it is unflattering. TREC CAsT 2019 ([arXiv 2003.13624](https://arxiv.org/abs/2003.13624)) evaluated 41 automatic runs and 24 manual runs on mean NDCG@3. Automatic median 0.286 (best non-BERT 0.360, and "the top two performing teams perform contextual query rewriting and expansion"); manual runs — which used **human-resolved** utterances created by two organizers with adjudicated disagreements, at ~5–10 minutes per ten-turn topic — median 0.361, best 0.589. Gap: 26% relative at the median, 35% at the best run. Turn-depth is the part that mirrors our 1-in-10 injection: automatic runs fall from ~0.3 at turn 1 to ~0.23 by turn 8 (−23%, statistically significant), while manual runs stay flat; "the manually resolved queries do not face the challenge of conversational query rewriting", and the manual/automatic gap more than doubles across the conversation. Automatic rewriting is therefore *the* measured bottleneck of multi-turn retrieval — and note the paper provides resolved utterances as ground truth, i.e. it evaluates the rewrite implicitly, never the rewriter in isolation.

Two data points on *deciding whether to rewrite*. "Adaptive utterance rewriting" classifies self-contained vs context-dependent utterances before specializing the rewrite; its BERT gate reaches F1 0.87/0.93 but still mislabels 8 of 68 self-contained utterances (11.8% false negatives), and its +201%/+215% P@1 gains are relative to the weak CAsT baseline ([Vakulenko et al., IR Journal](https://zenodo.org/records/8118164)). A 2026 BEIR study of prompt-only rewriting found nDCG@10 changes of **−9.0% on FiQA** (p<0.001), +5.1% on TREC-COVID, ~0 on SciFact; lexical substitution occurred in 95% of rewrites, so only its direction (toward corpus vocabulary; the CTF metric) predicted the sign; a feature-based "should I rewrite?" gate reached AUC 0.593 and could not beat never-rewriting (p>0.12); the oracle per-query ceiling was +3 pp ([Kotte, arXiv:2603.13301](https://arxiv.org/abs/2603.13301)). Its limitations state that conversational/underspecified queries are **not** evaluated there.

## 7. Environment state, and retrieval triggers other than "every turn"

Continue's autocomplete builds context automatically from the file prefix/suffix at the cursor, LSP definitions, matching imports, and "recently opened or edited files" ([autocomplete](https://github.com/continuedev/continue/blob/main/docs/ide-extensions/autocomplete/context-selection.mdx), [chat](https://github.com/continuedev/continue/blob/main/docs/ide-extensions/chat/context-selection.mdx)); `@Git Diff`, `@Terminal`, `@Problems` are explicit. FLARE triggers retrieval only when a token of the tentative *next sentence* falls below probability θ (θ=0 never, θ=1 every sentence) and uses that low-confidence span as the query ([FLARE](https://arxiv.org/pdf/2305.06983)). Self-RAG learns a `Retrieve` reflection token that decides when to search ([Self-RAG](https://arxiv.org/pdf/2310.11511)); Adaptive-RAG routes on a query-complexity classifier into no-retrieval / single-step / multi-step ([Adaptive-RAG](https://arxiv.org/pdf/2403.14403)). MemGPT's retrieval is agent-authored and paginated, nudged by a system prompt — "The answer to the users question will ALWAYS be in your archival memory, so remember to keep searching if you can't find the answer" — and degrades badly on weaker function-calling models (GPT-3.5) **[paper's own measurement]**. Generative Agents rank with `α_recency·recency + α_importance·importance + α_relevance·relevance`, all α=1, min-max normalized, recency an exponential decay over hours since last access; the "query" is the agent's current situation, and reflection-time queries are LLM-generated questions gated by an importance sum > 150 ([Generative Agents §4.1](https://ar5iv.labs.arxiv.org/html/2304.03442)). Being a weighted sum rather than a gate, **it cannot return an empty set** — yet the authors' error analysis still names failed memory retrieval as a dominant failure mode. The ablation (admittedly on believability, not retrieval metrics) shows each memory/reflection/planning component contributing, effect size ≈8 SD against the no-memory baseline.

## 8. What happens when the rewrite produces nothing

mem0 raises on an empty query. Graphiti drops the lexical channel silently (`''` → RRF over the rest). LangChain skips the LLM entirely when there is no history. LongMemEval's weak rewriter invented a range and lost recall. HyDE assumes non-ambiguity. query2doc's LLM asks a clarifying question instead of expanding. Nobody I found defines a *relaxation ladder* (what to return when the rewritten query still yields zero hits) — the closest published instruments are abstention scoring (LongMemEval's abstention question class) and Anthropic's 1−recall@20 failure metric.

## 9. Is retrieval ever measured on short/deictic turns specifically?

**No published measurement that I could find.** LongMemEval stratifies by question *type*, not by turn length or deixis. CAsT stratifies by turn depth — the closest published proxy, and it shows degradation *increasing* with depth, which is the same phenomenon we measured as 1 injection in 10 turns. Kotte's study explicitly excludes conversational/underspecified queries from its scope. The available proxies are indirect: HyDE's uni-modal assumption, mem0's ≤3-term tier, CAsT's turn-depth curve.

## 10. What transfers to a local, Markdown-only, FTS5-only vault

**Possible with no model call on the read path.** (a) *Query assembly from state the harness already holds*: append cwd path components, the git branch, the last-touched files, the last error string or failing test name from the previous tool result, and the previous user turn's content words — this is the model-free version of Continue's recently-edited-files context and of Graphiti's "recent episodes as seeds". (b) *Seed expansion instead of rewriting*: take the note paths injected last turn and expand via wikilinks, shared tags, same directory or day — the graph-BFS analog, zero model. (c) *A weighted admission score instead of a hard precision gate*: `score = w_lex·bm25 + w_recency·decay(updated) + w_prior·typePrior + w_anchor·(matched-last-turn)`, admitting candidates at zero lexical overlap; this is exactly the Generative Agents design, and it is what converts "0 hits → silence" into "0 hits → low-confidence recollection" (which our hint-only mode can then qualify). (d) *Query-length-adaptive normalization* of FTS5 `bm25()` output: mem0's five tiers port directly, and FTS5 column weighting (`bm25(notes, 5.0, 3.0, 1.0)` over title/tags/body) is the model-free way to buy back precision on 3-character prompts. (e) *Metadata-only fallback*: a query that carries no lexical content is still expressible as a filter — basic-memory's `search_notes` makes its `query` optional alongside frontmatter filters (`{tags:[…]}`, `{status:…}`, `{$between:[…]}`, default limit 10) ([metadata-search.md](https://github.com/basicmachines-co/basic-memory/blob/main/docs/metadata-search.md)). (f) *Write-time document expansion* — highest value, zero read-path cost, because the vault is already agent-authored: index a breadcrumb of path + title + type + tags + heading + glossary aliases beside the body (contextual BM25, model-free), keep aliases/术语 as data so "这个" resolves by a deterministic most-recent-mention tracker, and let the write path maintain a per-note aliases line. (g) *Cost/noise controls*: cap notes and characters (we already do, 900 code points), dedupe by path, add a per-session cooldown, and keep the candidate set small — LongMemEval found a weak reader degrades past ~3k retrieved tokens.

**Requires a model call on the read path.** HyDE and query2doc pseudo-documents; any genuine coreference rewrite of "那这个呢" (the condense prompts, or a trained self-containedness classifier); natural-language time-range extraction; log-prob cross-encoder reranking; and CJK entity extraction — the spaCy pipeline mem0 relies on has no Chinese NER, so that trick does not port as-is. Given query2doc's >2 s and the AUC 0.593 gate, a read-path model call buys a *rewrite that can lose recall* at a latency that breaks a per-turn hook; the measured wins sit on the write side and in the admission rule, both free.
