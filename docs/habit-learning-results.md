## 5. Pass 7：决定性的否证——**99% 的工具选择不是用户要求的**

问题：我统计的是 **agent 的工具调用**，但用户只输入一段提示词。
如果 agent 自己挑了 `grep`，那是 **agent 的默认行为**，不是用户的习惯。

测法：对每个回合，检查 agent 运行的每个工具，是否在**该回合用户自己的消息**里被点名。

| 工具 | 用户点名 | agent 自行选择 | 未被要求比例 |
|---|---|---|---|
| grep | 0 | 78 | **100%** |
| git | 0 | 63 | **100%** |
| node | 2 | 53 | 96% |
| npm | 1 | 41 | 98% |
| python3 | 0 | 27 | **100%** |
| curl | 0 | 21 | **100%** |
| prettier | 0 | 2 | **100%** |
| eslint | 0 | 2 | **100%** |
| rg / pnpm / vitest / jest | 0 | 各 1 | **100%** |
| **合计** | **3** | **291** | **99.0%** |

> **294 次工具选择里，291 次不是用户要求的。**

**这否证了设计草案 §4.1 的整个信号族。** 计数工具调用，测的是**这个插件的 agent 的默认行为**；
它跨所有用户都是常数，因此对"这个用户是谁"零信息量。

## 6. Pass 4：衰减无法标定（并更正我自己的一处错误）

**先说更正。** 我在 pass 4 的初版输出里写了
"半衰期 30 天，而语料只跨 67.9 天 → 没有任何笔记能达到 score<0.5"。**这句话是错的。**

正确算术：

```
67.9 天 / 30 天 = 2.26 个半衰期
0.5^2.26 = 0.209     → 低于 0.5（降级线）✅ 可达
0.15 需要 log(0.15)/log(0.5) × 30 = 82 天   → 超过 67.9 天 ❌ 不可达
```

所以**降级可达，归档不可达**。更正后的准确结论有两条，第二条才是致命的：

1. **没有年龄区间可拟合。** 67.9 天里只有 2.26 个半衰期，且绝大多数笔记是最近创建的。
   用这样的数据标定半衰期，等于用两个点拟合一条曲线。
2. **更根本：没有任何东西可供衰减。** vault 中标题以 `习惯：` 开头的笔记共 **9 条**：

   | assertion | status | 条数 |
   |---|---|---|
   | `stated` | `active` | 6 |
   | （未设置） | `active` | 3 |

   **`observed` 的习惯笔记：0 条。**

   而设计草案 §3.4 明确规定 `stated` **不参与衰减**。
   → **衰减机制的作用对象是空集。** 现在标定它没有意义；它只能在候选管线真正产生
   `observed` 笔记之后才可测。

## 8. 对设计的修正建议

1. **删除草案 §4.1 的 `toolchain:`/`ecosystem:`/`workflow:` 信号族。**
   实测 99% 不归用户所有。保留它们只会产出同义反复。
2. **改用"用户话语的跨会话复现"作为唯一信号**（草案 §4.1 的 `method:` 一路，从"仅 stated"扩展为"可计数"）。
   它与既有的 `习惯：` stated 路径**不重复**：既有的要求模型在**单回合**内注意到并输出；
   新路径发现的是**单个回合无法显示的跨会话复现**——正是 `SKILL.md` 说的那个空缺。
3. **`promoteAfter = 3` 可以定，但理由变了。** 在用户话语信号上，`>=3` 给 6 个候选、`>=9` 给 2 个。
   由于**隔离态**（草案 §3.1）已经把"精度"交给"不可检索 + 待确认"，
   候选阈值应当**偏低以保召回**（3），精度由隔离与人工确认承担。
   **这正是 CAPTURE 的 quarantine 设计意图。**
4. **衰减维持草案，但明确标注"未标定"。**
   作用对象当前为空集（0 条 `observed`），且语料仅 2.26 个半衰期。
   它的验收必须**推迟到候选管线产出真实 `observed` 笔记之后**，用当时的数据标定。
5. **保留"技能偏好不在范围内"的结论**（草案 §1.3），并新增：
   **工具偏好也不在范围内**（本次实测）。

## 9. Task 0 的局限

- **样本小**：40 个根会话、178 条用户消息、6 个项目、67.9 天。所有比例区间很宽。
- **项目严重不均衡**：`dsh-obsidian-mem` 占 82/107 个可用回合（77%）。
  其余 5 个项目合计仅 25 个回合，跨项目结论的置信度低。
- **"用户话语"词表是手写的 12 条**，不是从数据归纳的。它可能漏掉其他真实习惯，
  也可能把一次性要求误判为持久指令（如"先调研"只出现 2 次）。
- **会话以 90 秒空闲合并回合**（`captureIdleMs`），所以"回合"不等于"用户消息数"。
- 探针只读日志；未写入任何 vault、未改动仓库代码（`git status` 干净）。

## 10. Task 6 噪声压力验收（2026-10-11 补测）——**精度远低于标定所示**

TraceRetain（[arXiv 2606.29178](https://arxiv.org/abs/2606.29178)）的结论是：
记忆污染在**干净输入上看不见**，只有受控的噪声写入压力下才显现。
所以实现完成后专做了一次噪声验收，**它改变了结论**。

### 10.1 测法与结果

噪声不是随机文本，而是**真正的威胁形状**：含有词表词、但并非持久偏好的消息 ——
「把这段提交了吧」是任务，「commit 之前先跑测试」是一次性指令。

| 语料 | 会话数 | 结果 |
|---|---|---|
| 6 条**真实偏好**，各 5 个会话 | 30 | **6/6 全部提升**（召回 100%） |
| 18 条**偶发提及**，各 1 个会话 | 18 | **4/6 个标签被提升 = 67%** |

被误提升的标签：`提交`、`规格与计划`、`中文回答`、`解释原因`。

### 10.2 这不是 bug，是机制的**定义**暴露出来了

计数器测的是**词语复现**，而偏好只是词语复现的**子集**。
「三个不相关的会话各提到一次同一个词」与「一条偏好被说了三次」，在这个机制看来**完全一样**。

**§7 的 Task 0 标定看不到这一点**：它统计的是每个词出现在多少个会话里，
从未区分偏好与提及 —— `提交` 的 18 个会话里既包含「以后改动完就提交」，
也包含「把这段提交了吧」。**那个 18 是词语复现的次数，不是偏好的次数。**

**阈值救不了这件事。** 常见词在任何足够长的历史里终究会复现；
把 `promoteAfter` 从 3 调到 9 只是延后，不是修正。已实测：bar=9 时 18 条偶发语料提升 0 条，
但标定中真实的 `解释原因`(5)、`中文回答`(3)、`简洁`(3) 也一并丢失。

### 10.3 真正的防线是隔离态，不是阈值

这恰好是设计 §3.1 的隔离态在承担精度：

- 每条被提升的候选都是 `status: provisional` + `assertion: observed`，**不进简报**；
- 被误提升的候选，其内容仍然是真的 —— 笔记说的是「插件在 3 个会话里看到过这个词」，
  这句话确实为真；错的只是**把它读作偏好**这一步；
- 所以错一条候选的代价是**审阅队列里多一行**，而不是每条简报里多一条错规则。

SAFETY 测试对**两个语料都**断言了这一点（真提升与误提升一视同仁）。

### 10.4 由此产生的记录与后续

| 项 | 处置 |
|---|---|
| `promoteAfter` 默认值 | **保持 3**（召回优先，精度由隔离态承担） |
| 误提升率上界 | **75%**，写进 `test/habit-noise.test.js` 的常量并附实测数字 67% |
| 改进方向 | **指令形状过滤**：偏好多写成一般性表述（「以后…」「一律…」「统一…」），偶发提及多指向具体对象（「把这段…」「这个…」）。**但这是一条未标定的启发式，不在本次实现中落地** —— 本轮已经因为「留了一条从不命中的词表条目」而删过一次，不在缺乏数据时再加一条。它有独立的标定工作。 |

### 10.5 局限

- 语料是**手写的 24 条消息**，不是真实历史。它构造了重叠形状，但比例是人为的。
- **真实历史里的误提升率没有被测量过** —— 要测它需要人工标注真实消息，本次未做。
- 因此 67% 应读作「这个机制在噪声下的量级」，不是「真实场景的误报率」。

## 11. 未验证 / 局限

**Task 0 与 Task 6 合并后的完整清单。**

1. **衰减的 `halfLifeDays = 30` 是借来的，不是标定的。** 它来自 limbic 默认值及其引用的
   Microsoft 研究 "~29 days optimal for production"。语料仅 2.26 个半衰期，且
   `archive_below = 0.15` 需要 82 天，超出语料跨度。**无法标定。**
2. **衰减在真实笔记上的行为未经测量** —— 单元测试用合成时钟，归档路径在真实 vault 上端到端验过，
   但"真实年龄的真实笔记会怎样"没有数据。触发条件记在计划的 Task 8。
3. **真实历史里的误提升率没有被测量。** Task 6 的 67% 来自手写语料，量级可信、比例人为。
   要测真实误报率需要人工标注真实消息，未做。
4. **词表不完整是结构性的。** 12 条里 4 条命中 0 次；换一种说法就学不到。阈值救不了召回上限。
5. **技能使用与工具链使用都不是信号**（实测 12/8847 ≈ 0.14% 与 99% 归 agent）。
6. **样本小且不均衡**（见 §9）。`promoteAfter = 3` 应在数据积累后重新标定。
7. **本文件是本地记录，不进版本库**（`docs/` 被 `.gitignore` 忽略），随包不发布。
