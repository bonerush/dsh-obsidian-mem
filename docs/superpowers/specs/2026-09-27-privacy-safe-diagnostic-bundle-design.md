# 用户诊断包设计

- **日期**：2026-09-27
- **状态**：待用户审阅的设计；尚未实现
- **适用入口**：DSH 插件、Codex MCP 适配器，以及独立命令行

## 目标与边界

用户运行 `dsh-obsidian-mem-diagnose --output <file>.json`，得到一个可直接打开、检查并自行附在 GitHub Issue 中的诊断包。命令行在插件无法加载时仍须报告可执行的检查结果。插件默认把有限的、无正文的调用决策暂存本机，以便进程退出后仍能解释近期失败。

诊断程序绝不读取或导出用户对话、会话日志、pending job 正文或模型输出、vault 笔记、提示词、工具参数、原始宿主日志、凭据、环境变量值和用户配置文件全文。它不上传数据，不改用户配置，不在 vault 中写文件。普通插件的自动蒸馏仍遵循 README 已说明的模型调用边界；本设计只约束新增诊断通路。

## 选择的方案

选择**本地白名单事件日志 + 独立命令行**。现有 `lib/debug.js` 已把事件类别和字段限制在封闭集合，但 `mem_admin(action="diagnostics")` 的 200 条环形缓冲在进程退出时清空。独立命令行无法事后读取该缓冲，所以两者共享一次记录、两个视图：当前环形缓冲继续服务 `mem_admin`，新增的本地日志保存严格缩减后的事件；命令行只读取该日志和受控的环境状态。

不通过本地 IPC 查询活进程，因为插件加载失败时不可用；不收集宿主日志再做事后脱敏，因为那些日志的内容与格式不受本插件控制。一个版本化 JSON 文件足以容纳报告，用户能够在上传前直接检查，无需新增压缩依赖。[GitHub 附件文档](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/attaching-files)当前列出 JSON 作为 Issue 评论附件格式，并说明公开仓库附件可被任何人访问；产品文档必须直说这一点。

## 数据流与模块

1. `createDiagnostics` 在现有字段校验后，将事件交给可选的持久化 sink。sink 的失败不得改变捕获、索引、写入或工具调用的结果；环形缓冲仍可用。`enabled: false` 的插件不创建任何诊断目录。DSH 与 Codex 两个入口把同一 `resolveDataRoot()` 结果交给 sink。
2. 新的诊断日志模块在 `$DSH_HOME/data/obsidian-mem/diagnostics/` 中为每次进程启动分配随机 run ID 和独立文件，目录权限 `0700`，文件权限 `0600`。不使用 PID、主机名、仓库名或项目名作文件名。并发进程各写各的文件；日志写入与轮转不得触碰 pending 队列或 vault。
3. 每条落盘事件仅含 run ID、递增序号、UTC 时间、既有事件类别、受控的 outcome/code、非负计数，以及需要时的短别名。`projectId`、`jobId`、`txId` 在写入前按本次 run 映射成 `p1`、`j1`、`t1` 等别名；原值及映射表不落盘。任何不在明确词表内的 outcome/code 写作 `other`；无法通过校验的字段直接省略。
4. 单个 run 最多保留最近 200 条且单文件最多 128 KiB，超限时删除最旧事件并记录丢弃计数。下一次插件启动时清理最后写入时间超过 7 天的文件；若另一进程仍持有一个长期空闲的旧文件，其下次记录须新建 run 文件。导出时忽略过期文件但不删除；没有进程运行期间不承诺后台定时清理。崩溃可能丢失最后尚未完成的日志写入，报告必须标示窗口范围与丢弃量。
5. 插件启动时在该 run 的日志头中写入本设计允许的配置摘要；若插件未能启动，命令行相应字段标为 `unavailable`，不回头读取用户配置文件。命令行入口仅依赖 Node 标准库作基础检查与报告写入。它在独立的读入模块中逐条验证日志版本、字段和值，重新构建固定输出对象，绝不把原始文件作为附件成员复制进去。插件模块加载失败不阻止基础报告生成。

## 诊断包契约

单个 UTF-8 JSON 文件包含 `format`、`schemaVersion`、`generatedAt`、`environment`、`checks`、`eventWindow`、`events` 和 `limitations`。`environment` 只允许插件版本、Node 版本、可可靠识别的 DSH 版本、操作系统类型与架构，以及下列配置摘要：`enabled`、`autoCapture`、`injectBrief`、`indexBackend`、`distill.dryRun`。无法取得的值为 `unavailable`，不得通过扫描用户配置文本去猜。

`events` 只含上一节的落盘字段；最多输出最新 200 条。`eventWindow` 说明覆盖的 run 数、时间边界、丢弃或损坏的记录数。报告整体上限 256 KiB；达到上限时缩减最旧事件并说明截断。不要加入绝对或相对路径、原始标识符、用户名、主机名、模型或提供方名称、仓库 remote、异常消息、堆栈、CLI 参数和环境变量。时间会透露使用时段，因此文档要求用户先检查 JSON 再上传。

命令行只在用户提供 `--output` 后创建文件，拒绝覆盖现有文件或跟随符号链接；完成文件权限为 `0600`。终端打印输出位置和摘要，但路径不写入报告。没有自动上传或后台上报。源文件缺失、过期或损坏标为 `unavailable`/`partial`，不能写作 `pass`。若输出目录不可写，返回明确的固定错误码，不留下半成品报告。

## 自检范围

基础检查不加载插件，也不读取对话相关文件：

- Node 是否达到仓库声明的最低版本；内存 SQLite 是否启用 FTS5。
- 随包入口、清单和命令行文件是否存在；版本能否读取。
- 数据根与诊断目录是否存在、可读，以及权限是否过宽；不输出其路径。
- 诊断日志能否按版本和白名单解析；过期、损坏、丢弃数量是多少。
- pending 目录中普通文件的数量，仅统计目录项，不打开 job 文件，也不输出文件名。

可加载插件时，在新建的临时 `DSH_HOME` 与临时 vault 下执行最小工具契约检查，确认 `mem_admin(action="diagnostics")` 返回有效结构。插件导入或自检失败只记录固定检查 ID、状态和机器码，不记录异常原文或堆栈。临时目录在结束后删除。这个自检不声称真实用户 vault、宿主会话钩子、模型路由或持久队列一定健康。

## 失败与安全规则

- 日志写入失败不得改变现有插件的调用结果；当前进程的 `mem_admin` 环仍可独立回答。命令行把日志缺口作为 `partial` 呈现。
- 日志读取拒绝符号链接、超出大小上限的文件、未知 schema 和非法字段。遇到坏记录继续处理其他 run，绝不把坏记录的原始内容放入报告。
- 不读取真实 vault 或真实用户配置，不运行仓库测试套件，也不安装依赖。所有诊断自检的写入仅限临时目录及用户指定的报告路径。
- 用户自行决定是否把报告附在 Issue 中。README 英中两版都解释字段、限制、检查方式与公开附件的可见性。

## 实施与验收

实现涉及 `lib/debug.js`、新的日志/导出模块、`lib/index.js`、`codex/server.mjs`、包的 CLI `bin` 入口、`package.json`、打包验证器、双语 README、`README.i18n.yaml`、CHANGELOG 和相应测试。新行为先写失败测试，再实现到通过；不增加运行时依赖。若新增 `lib/` 模块或层级，先在 `test/architecture.test.js` 登记并说明预算。

验收必须覆盖：真实记录路径中的对话/标题/路径/提示词哨兵无法出现在落盘日志和最终 JSON；标识符只留下短别名；未知 outcome/code 不原样流出；两进程文件不冲突；容量、保留期、损坏日志、符号链接、只读目录和已有输出文件的行为；`enabled: false` 不落盘；插件导入失败时基础报告仍能生成；自检只在隔离临时目录写入；打包后 CLI 确实存在。使用临时 `DSH_HOME` 和 vault，运行 `npm run check`、`git diff --check`，核对真实 tarball 与双语 README 哈希。测试结果与尚未验证的能力记入 CHANGELOG，不把设计通过误写成产品已验证。
